1. Project Overview

This report documents the development of an automated fascia and vein detection system for B-mode peripheral vascular ultrasound. The goal is to identify two anatomical structures in every ultrasound frame:

  • Fascia — the thin, curvilinear echogenic band separating subcutaneous fat from underlying muscle. Serves as the primary anatomical landmark for probe positioning and CHIVA shunt classification.
  • Vein lumen — the anechoic (dark) oval cross-section of peripheral veins (saphenous, perforators, and deep veins) visible below or at the fascia.

The approach uses BiomedParse, a foundation model for biomedical image segmentation, fine-tuned on a custom-labelled peripheral vascular ultrasound dataset collected from clinical examination videos.

Key result: Fine-tuning increased fascia detection from a mean IoU of 0.045 (pretrained, essentially no detection) to 0.829 — an 18× improvement. Vein detection remained strong throughout (pretrained baseline IoU 0.736; fine-tuned 0.729).

2. Model Architecture

2.1 BiomedParse (GeneralizedSEEM)

BiomedParse is built on top of SEEM (Segment Everything Everywhere all at once), a universal segmentation model extended for biomedical imaging. It accepts multimodal prompts — free-text, visual references, spatial points — and produces segmentation masks.

2.2 Component Details

Backbone — Focal Transformer

A hierarchical vision transformer with focal attention that captures both fine-grained local detail and long-range context simultaneously. Outputs four feature maps at resolutions res2–res5 (stride 4, 8, 16, 32). During fine-tuning the backbone was frozen to preserve the learned visual representations.

Pixel Decoder — Multi-scale FPN

A deformable transformer encoder fuses the four backbone feature maps into a dense multi-scale representation. Also frozen during fine-tuning — only the mask predictor (transformer decoder) was trained.

Mask Predictor (SEEM Transformer Decoder)

The decoder maintains 101 object queries. During grounding inference (task='grounding_eval'), the text embedding is injected as grounding tokens into the cross-attention layers. Each query produces a mask proposal; the best query is selected by maximum probability mass: 

probs = sigmoid(all_gmasks)          # [101, H, W]
weighted = probs.reshape(101, -1).max(dim=1).values
best_query = weighted.argmax()       # index of best proposal

Text Encoder — BiomedBERT

Microsoft's BiomedBERT (base, uncased, abstract-fulltext variant) tokenises and encodes the text prompt. Its weights were also frozen during fine-tuning.

2.3 Dual-Model Inference

The deployed system uses two separate model checkpoints for a single image:

  • Fascia model (fascia_finetuning_v2_production) — fine-tuned on fascia-only data, uses top_bias=True to weight query selection toward the upper portion of the image (fascia sits near the top).
  • Vein model (fascia_vein_finetuning) — continued fine-tuning from the fascia checkpoint on combined fascia+vein data.

Both models share identical architecture and config; only the checkpoint weights differ. Both inference passes run with torch.no_grad() on GPU.

3. Dataset

3.1 Source Material

Ultrasound frames were extracted from clinical examination videos captured during CHIVA varicose vein assessments. The videos cover multiple patients and probe positions across the lower limb (thigh, calf, popliteal fossa). All images are B-mode (greyscale) peripheral vascular ultrasound from a single machine and acquisition protocol.

Category remapping: BiomedParse's output head has 16 built-in classes (IDs 0–15). Our custom IDs 17 and 18 exceed this range and are remapped during training: fascia (17) → histology structure (14), vein (18) → vessel (7). This means the model reuses existing vocabulary slots rather than learning new classes from scratch.

3.3 Dataset Format

The dataset follows COCO-style JSON annotation format with one key difference: masks are stored as separate PNG files rather than inline polygon coordinates. 

{
  "images":      [{ "id": 0, "file_name": "000000_Ultrasound_PeripheralVascular.png",
                    "height": 1024, "width": 1024 }],
  "annotations": [{
    "id": 0,  "image_id": 0,  "category_id": 17,
    "mask_file": "000000_Ultrasound_PeripheralVascular_fascia+layer.png",
    "sentences": [{ "raw": "fascia layer in PeripheralVascular Ultrasound" }]
  }],
  "categories":  [... 19 entries (0–18) ...]
}

Each annotation contains a sentences field — the text grounding query used during training. During the training loop, a random sentence from the list is selected per sample (data augmentation).

Mask PNG format

Mask images are single-channel PNGs with pixel value 1 for the annotated structure and 0 for background. The dataset mapper reads them as RGB, sums the three channels (producing 3 for structure pixels), then thresholds: mask = (sum == 3).

3.4 Image Pre-processing (Training)

The BioMedDatasetMapper applies the following transforms to every training sample:

  1. ResizeScale — randomly scales the image so the shorter side falls between 0.9× and 1.1× of 512 px (slight scale jitter).
  2. FixedSizeCrop — crops to exactly 512×512.
  3. RandomRotate — with 50% probability, rotates by 90°, 180°, or 270° (controlled by RANDOM_ROTATE: True in config).
  4. Normalisation: pixel mean [64.28, 59.29, 59.96], std [62.48, 60.87, 59.84] (BioMed-specific values, different from ImageNet).

4. Fine-Tuning Methodology

4.1 Starting Point

Fine-tuning begins from biomedparse_v1.pt — Microsoft's publicly released pretrained checkpoint trained on a large corpus of biomedical imaging data (radiology CT/MRI, pathology slides, endoscopy, etc.). This checkpoint has never seen peripheral vascular ultrasound during pretraining.

4.2 Phase 1 — Fascia-Only Fine-Tuning

The first phase trains exclusively on the 2,364 fascia samples.

What is frozen vs trained: Only the mask predictor transformer decoder is updated. The Focal Transformer backbone, FPN pixel decoder, and BiomedBERT text encoder are all frozen. This is critical — the pretrained representations are preserved while only the task-specific decoding head adapts to ultrasound fascia.

The best checkpoint (fascia_finetuning_v2_production, epoch 10, step 1470) is selected by highest validation IoU. This checkpoint is used as the production fascia model.

4.3 Phase 2 — Combined Fascia + Vein Fine-Tuning

Phase 2 continues from the Phase 1 fascia checkpoint. The training set is expanded to include both fascia (2,364) and vein (1,731) samples — 4,095 total.

The best Phase 2 checkpoint (fascia_vein_finetuning) is used exclusively for vein prediction in the deployed system, while the Phase 1 fascia checkpoint continues to be used for fascia prediction. This two-model design was adopted after observing that the combined model produced lower absolute probability scores for fascia, causing detection to degrade when a single model was used for both tasks.

4.4 Inference-Time Adaptations

Top-Bias Query Selection (Fascia)

Fascia always appears in the upper portion of an ultrasound frame. A vertical weighting is applied during best-query selection to bias toward proposals with signal near the top: 

vert_weight = torch.linspace(2.0, 0.2, H).view(1, H, 1)  # 2.0 at top → 0.2 at bottom
weighted = (probs * vert_weight).reshape(101, -1).max(dim=1).values
best_q   = weighted.argmax()

VLM Evaluator (Vein)

Vein detection can produce false positive blobs from muscle echogenicity or speckle. An optional VLM evaluator passes each predicted blob — drawn as a green outline on the full ultrasound frame — to qwen/qwen3.6-27b (vision model via Groq API). The model judges whether the outlined structure is a real vein based on full anatomical context (fascia position, tissue depth, shape). Only confirmed blobs are kept.

5. Experiments

5.1 Experimental Setup

Three model configurations are evaluated on the same 720-image held-out test set:

  • Baseline — Original biomedparse_v1.pt with no fine-tuning. Uses the same grounding inference pipeline with the same text prompts.
  • Phase 1 FT — Fascia-only fine-tuned model (fascia_finetuning_v2_production). Evaluated on fascia test set only.
  • Phase 2 FT — Combined fascia+vein fine-tuned model (fascia_vein_finetuning). Evaluated on vein test set only.

5.2 Evaluation Protocol

Each image is processed with the same _grounding_prob pipeline used in the deployed application: 512×512 resize, grounding_eval task, threshold 0.5 for binary prediction. Metrics are computed against binary ground-truth masks (pixel value > 0). 

IoU  = |pred ∩ gt| / |pred ∪ gt|
Dice = 2 × |pred ∩ gt| / (|pred| + |gt|)

Results are mean values across all test samples. Skipped samples (exceptions) are noted separately and excluded from the mean.

7. Discussion

7.1 Why Fascia Required Fine-Tuning

Fascia as a distinct anatomical target does not appear in BiomedParse's pretraining corpus. The model has no concept of a thin curvilinear echogenic band in ultrasound — it segments organs, tumours, histological structures. The baseline IoU of 0.045 confirms the model essentially produces random noise when asked for fascia.

After Phase 1 fine-tuning, the mask predictor learns to associate the text embedding of "fascia layer in PeripheralVascular Ultrasound" with the characteristic thin bright band near the top of the image. The improvement is entirely in the mask predictor decoder; the frozen backbone still extracts the correct visual features (bright thin horizontal structures), the decoder simply could not previously select the right proposal.

7.2 Domain Shift on Unseen Images

When tested on ultrasound images from other machines or with different gain/brightness settings (e.g., images sourced from the internet), the fine-tuned model produces excessive false positive detections. This is expected — all 4,095 training samples come from a single machine and acquisition protocol. The model has overfit to this specific image distribution.

Two mitigations are implemented in the deployed application:

  • CLAHE toggle — Optional contrast-limited adaptive histogram equalisation normalises the input image histogram before inference, reducing the visual distribution gap between the test image and training data.
  • VLM Evaluator toggle — The Qwen3 vision model filters false positive vein blobs by evaluating full-image anatomical context (fascia position, tissue depth, structure shape).

7.3 Two-Model Architecture

An early design used a single combined checkpoint (Phase 2) for both fascia and vein. This was abandoned after observing that the Phase 2 model produced lower absolute sigmoid probabilities for fascia compared to Phase 1 — the model partially re-distributed its representational capacity toward vein. Using Phase 1 for fascia and Phase 2 for vein independently restored fascia detection quality without any trade-off in vein detection.

7.4 Inference Design Choices

Top-bias query selection for fascia was motivated by the consistent anatomical position of fascia in the upper image region. Without the spatial weight, the decoder occasionally selected a deep muscle proposal as the best match even when a correct fascia proposal existed — the top-bias corrects this without any additional training.

Post-processing for fascia converts the predicted probability map to two smooth curvilinear lines (superficial and deep edges of the fascial zone) using column-wise edge detection and multi-pass box smoothing. This matches the clinical annotation style — sonographers mark fascia as a line, not a filled region.

8. Conclusions

  • Fine-tuning BiomedParse on 2,364 labelled fascia frames increased fascia IoU from 0.045 → ~0.829 (18× improvement).
  • The pretrained model already achieves reasonable vein detection (IoU 0.736) due to prior vessel segmentation training; domain-specific fine-tuning on 1,731 vein samples further refines this to the specific appearance of peripheral vascular ultrasound veins.
  • Only the mask predictor decoder (≈18% of parameters) was trained; backbone, pixel decoder, and text encoder remain frozen, preventing catastrophic forgetting.
  • The deployed system uses two separate checkpoints — one per structure — to eliminate cross-task interference observed with a single combined checkpoint.
  • Domain shift on non-training-distribution images is the main remaining limitation; adding training diversity (brightness/contrast augmentation or multi-machine data) would address this in future iterations.
